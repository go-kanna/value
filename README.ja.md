kanna-value は、値を 1 つ保持する構造体と `validate` メソッドから値オブジェクトを生成します。コンストラクタ、アクセサ、JSON と SQL のメソッドがそろい、値がどこから来ても、ルールを満たすものしか保持しません。定数を持つ string 型を、外部からは定数の値だけを読み込む enum にすることもできます。

[kanna](https://go-kanna.github.io/ja/) コードジェネレータファミリーの 1 つです。Go 1.26 以上が必要です。

## インストール

```sh
go get -tool github.com/go-kanna/value/cmd/kanna-value
```

ルールはパッケージ `github.com/go-kanna/value/rule` で書きます。上のコマンドで依存に追加されます。標準ライブラリ以外には依存しません。

## 使い方

非公開フィールドを 1 つ持つ構造体に値を保持し、ルールを `validate` メソッドとして書きます:

```go
package model

import (
	"time"

	"github.com/go-kanna/value/rule"
)

//go:generate go tool kanna-value

var opened = time.Date(2020, 4, 1, 0, 0, 0, 0, time.UTC)

//kanna:value
type Email struct{ s string }

func (Email) validate(s string) error { return rule.Email(s) }

//kanna:value
type CompletedAt struct{ t time.Time }

func (CompletedAt) validate(t time.Time) error {
	if t.Before(opened) {
		return rule.FailWith("greater_than_or_equal_to", map[string]any{"count": opened})
	}
	return nil
}
```

`go generate ./...` を実行すると、同じディレクトリに `value_gen.go` が書き出されます:

```go
// Code generated by kanna-value. DO NOT EDIT.

func NewEmail(v string) (Email, error)           // checks v with validate
func MustEmail(v string) Email                   // for a constant: panics if v is rejected
func (x Email) String() string                   // the string held
func (x Email) IsZero() bool
func (x Email) MarshalJSON() ([]byte, error)     // checks what it encodes
func (x *Email) UnmarshalJSON(data []byte) error // checks what it decodes
func (x Email) Value() (driver.Value, error)     // checks what it writes
func (x *Email) Scan(src any) error              // checks what it scans

func NewCompletedAt(v time.Time) (CompletedAt, error)
func MustCompletedAt(v time.Time) CompletedAt
func (x CompletedAt) Time() time.Time
func (x CompletedAt) Equal(y CompletedAt) bool
// String, IsZero, MarshalJSON, UnmarshalJSON, Value, and Scan, as for Email
```

フィールドは非公開なので、パッケージの外で値を得る手段は `NewEmail`、`MustEmail`、`UnmarshalJSON`、`Scan` だけで、どれも `validate` を実行します。`Email` を受け取るコードは、もう一度チェックする必要がありません。ただし、`var e Email` のように Go が `validate` を通さずに作るゼロ値は例外です。ゼロ値は `IsZero` で分かります。`MarshalJSON` と `Value` も `validate` を実行するので、ルールが拒否するゼロ値は、読み戻せずに失敗するのではなく、書き出す時点で、設定し忘れたフィールドのようにゼロ値だと言うエラーで止まります。値がないことのあるフィールドは、JSON の null と SQL の NULL で nil のままになるポインタ `*Email` にするか、`json:",omitzero"` タグを付けます。

値オブジェクトは独立した型なので、エラーやドキュメントには付けた名前のまま現れ、他の型と同じようにメソッドを定義できます:

```go
func (e Email) Domain() string {
	_, domain, _ := strings.Cut(e.s, "@")
	return domain
}
```

値オブジェクトにできない構造体があると、実行時に値を扱う段階まで持ち越さず、生成の時点で止まります:

```console
$ go generate ./...
./model.go:6:6: error: Email has no validate method to check its values with
  add func (Email) validate(string) error, returning nil to accept the value
./model.go:9:17: error: ID.Value must be unexported, so that a value is set only through the generated code
  rename it to value
./model.go:14:19: error: Tags holds a []string, which has no name to call the method returning it after
  declare a named type for it, and hold that
./model.go:21:1: warning: "//kanna:valeu" is not recognized as a directive
  did you mean "//kanna:value"?
./model.go:25:1: warning: //kanna:enum is not attached to a declaration, so nothing reads it
  write it right above what it marks, with no blank line between
```

生成されるものは、生成前から呼び出していても構いません。型を kanna-value に移行するときや、呼び出し側を先に書くときなどです。kanna-value は読み込んだパッケージを、これから書き出す内容を組み込んだ状態でもう一度型チェックし、コンパイルが通らない間は何も書き出しません。コンストラクタがないために隠れていた間違い、たとえば値オブジェクトにないメソッドの呼び出しも、このとき報告されます。

値オブジェクトを読み取る別のジェネレータのパッケージ（kanna-mapper のパッケージなど）には、その `value_gen.go` が存在している必要があります。そのため初回の実行では、値オブジェクトのパッケージを先に生成してください。

kanna の生成器を 2 つ以上使うなら、必要な順に動かす [`go tool kanna gen`](https://github.com/go-kanna/kanna) で動かしてください。

## 生成されるもの

フィールド `t` に型 `T` の値を保持する構造体 `X` について、次のものが生成されます:

| 宣言 | 内容 |
|---|---|
| `NewX(v T) (X, error)` | `validate` が受け入れれば `v` を保持する `X` を、拒否すればそのエラーを返す |
| `MustX(v T) X` | 定数など、有効だと分かっている値のための `NewX`。`v` が拒否されると panic する |
| アクセサ | 値を返す。名前は `T` から決まる: `string` は `String`、`int64` は `Int64`、`time.Time` は `Time`、`uuid.UUID` は `UUID` |
| `String() string` | 値に `String` があればそれを、なければ fmt の `%v` を使う。`string` の場合はアクセサそのもの |
| `IsZero() bool` | 値に `IsZero` があればそれを、なければゼロ値との `==` を、スライスとマップでは `== nil` を使う |
| `Equal(y X) bool` | `time.Time` のように `T` が `Equal(T) bool` を持つ場合のみ生成される |
| `MarshalJSON`, `UnmarshalJSON` | `validate` が受け入れた場合に、`T` と同じようにエンコードする。`T` としてデコードし、`validate` が受け入れた場合のみ保持する |
| `Value`, `Scan` | database/sql が `T` を両方向に変換できる場合のみ生成される。`validate` が受け入れた場合に、database/sql が `T` を変換するのと同じように変換する。`T` としてスキャンし、`validate` が受け入れた場合のみ保持する |

非公開の構造体には、非公開のコンストラクタ `newX` と `mustX` が生成されます。

`T` によって、次のことが決まります:

- `T` は基本型か名前付き型で、その名前からアクセサの名前が決まります。スライスは `type tags []string` のように独自の型を通して保持します。
- 金額と通貨のように複数の値を持つときは、それらを 1 つの構造体にまとめて保持します。`type Amount struct{ Units int64; Currency string }` を `type Money struct{ a Amount }` で保持すると、アクセサは `Amount` です。ほかのパッケージから `NewMoney` を呼べるように、構造体は公開します。非公開の型の値は、パッケージの外では書けないからです。
- `T` は、名前の有無によらず、ポインタ、チャネル、関数にはできません。参照する先を値を作った側と共有し、`validate` のあとで書き換えられるからです。ポインタは、`*url.URL` ではなく `url.URL` のように、指す先を保持します。
- スライスとマップは、受け取るときと返すときに `slices.Clone` または `maps.Clone` でコピーされるので、`validate` を通った後に変更されることはありません。ただし、要素の中身まではコピーされず、構造体の中のスライスもコピーされません。その場で変更されない値を保持してください。
- `IsZero` は Go と同じ基準でゼロ値を判定します。nil スライスはゼロ値ですが、空のスライスは違います。`==` でも `== nil` でも独自のメソッドでもゼロ値を判定できない `T`（スライスを持つ構造体など）には `IsZero` が生成されず、encoding/json の `omitzero` はリフレクションにフォールバックします。
- ゼロを渡すことと何も渡さないことは区別されません。価格の 0 のようにルールがゼロ値を受け入れる場合、`MustPrice(0)` は `Price{}` と等しく、`IsZero` はどちらもゼロと判定し、`omitzero` はどちらも省略し、kanna-validator の `required` はどちらも `blank` と報告します。ゼロという値と値がないことを区別したい場合は、`*Price` で保持し、値がないときは nil にしてください。
- `Equal` があるのは、時刻では `==` が正しく判定できないことがあるからです。同じ時刻でも、片方がモノトニッククロックの読み取り値を持っていたり、ロケーションが異なっていたりすると `==` では異なるものになります。データベースから読み戻した時刻がこれにあたります。
- database/sql が `T` を両方向に変換できるのは、`T` が bool、複素数以外の数値、文字列、`[]byte`、`time.Time`、`uuid.UUID` の場合と、`T` の値が `Value() (driver.Value, error)` を、ポインタが `Scan(any) error` を持つ場合です。`type tags []string` のようなそれ以外の `T` には、`Value` と `Scan` を生成しません。生成しても、どの値でも失敗するからです。保存したい場合は、自分で書いてください。nil の `[]byte` は空として書き出します。database/sql は NULL として書き、`Scan` が拒否するからです。

デコードとスキャンは、エラーの場合も JSON の null の場合も、値を変更しません。NULL のカラムはエラーになります。NULL になりうるカラムは `*X` にスキャンしてください。その場合 database/sql が nil を設定します。

生成される名前と同じ名前のメソッドやコンストラクタを自分で書いている場合は、上書きせずに生成を止めます。生成されない場合の `Equal`、`IsZero`、`Value`、`Scan` は、自分で書いて構いません。

## Enum

宣言した定数の値だけを取る string 型には、`//kanna:enum` を付けます:

```go
//kanna:enum
type OrderStatus string

const (
	OrderStatusPlaced   OrderStatus = "placed"
	OrderStatusPaid     OrderStatus = "paid"
	OrderStatusShipped  OrderStatus = "shipped"
	OrderStatusCanceled OrderStatus = "canceled"
)
```

`go generate ./...` を実行すると、`value_gen.go` に次のものが追加されます:

```go
func NewOrderStatus(v string) (OrderStatus, error)    // OrderStatus(v), if it is the value of a constant
func OrderStatusValues() []OrderStatus                 // the constants in the order they are declared, in a new slice
func (x OrderStatus) String() string                   // the underlying string; implements fmt.Stringer
func (x OrderStatus) MarshalText() ([]byte, error)     // checks what it encodes
func (x *OrderStatus) UnmarshalText(text []byte) error // checks what it decodes
func (x OrderStatus) MarshalJSON() ([]byte, error)
func (x *OrderStatus) UnmarshalJSON(data []byte) error
func (x OrderStatus) Value() (driver.Value, error)
func (x *OrderStatus) Scan(src any) error
func (x OrderStatus) Validate() error                  // whether x is the value of a constant, which kanna-validator calls
```

定数が複数のファイルにあるときは、ファイル名の順に並び、ファイルの中では宣言した順に並びます。

`String` は検証せずに元の文字列を返します。ゼロ値や、直接キャストした未検証の値でも同じです。他の生成メソッドと同じく、手書きの `String` メソッドがある場合は削除してから生成してください。

コンストラクタと、デコード、スキャン、エンコード、書き出し、検証のメソッドは、どの定数でもない値を `rule.Fail("inclusion")` で拒否します（kanna-validator の `oneof` が報告するのと同じコード）。デコードとスキャンは、エラーの場合も JSON の null の場合も、値を変更しません。NULL のカラムは、値オブジェクトと同じくエラーになります。

型は定数を持つ string 型のままなので、定数に対する `switch`、switch の網羅性を調べる linter、定数を読み取る他のジェネレータは、これまでどおり動きます。プログラム内では、他の string 型と同じく `OrderStatus("shiped")` もコンパイルが通るので、値は定数か `NewOrderStatus` で作ってください。そのどちらからも作られなかった値は `Validate` で検出でき、`MarshalText`、`MarshalJSON`、`Value` も同じく拒否するので、書き出したものは読み戻せます。ゼロ値も定数ではないので、書き出すと、設定し忘れたフィールドのようにゼロ値だと言うエラーで止まります。値がない場合があるなら、JSON の null と SQL の NULL で nil のままになる `*OrderStatus` を使うか、`json:",omitzero"` タグを付けてください。`"shiped"` のような定数は、[`kanna-value vet`](#enum-に渡す定数を検査する) がプログラムを動かす前に見つけます。

定数 1 つが enum の値 1 つで、enum を読む生成器はそれを 1 つずつ扱います。そのため、同じ値を持つ 2 つの定数は、コピーの誤りと同じく生成を止めます。既定値のように、ある値に別の名前を付けたいときは、関数で書きます:

```go
func DefaultOrderStatus() OrderStatus { return OrderStatusPlaced }
```

生成できない enum は、生成を止めます:

```console
$ go generate ./...
./order.go:5:6: error: OrderStatus has no constants to be one of
  declare them beside it, such as const OrderStatusA OrderStatus = "a"
./order.go:12:2: error: OrderStatusSettled holds "paid", as OrderStatusPaid does
  give each constant a value of its own
  or, to name OrderStatusPaid otherwise, declare func OrderStatusSettled() OrderStatus instead
./order.go:13:2: error: OrderStatusNone holds "", the zero value of OrderStatus, which stands for none
  remove it, and use a *OrderStatus where a value may be absent
./order.go:20:6: error: Kind is not a struct, which //kanna:value marks
  mark it //kanna:enum to accept only the constants declared beside it
```

非公開の enum には、非公開の関数 `newX` と `xValues` が生成されます。

## enum に渡す定数を検査する

enum は string 型のままなので、Go はどの文字列の定数からでも enum の値を作ります。その値を持つ定数があるかどうかは問いません。`o.Status == "shiped"` はコンパイルが通りますが、enum が宣言したどの値にも一致しません。`o.Status = "shiped"` もコンパイルが通りますが、`Validate` が拒否する値を入れます。database/sql はその値をそのまま書き込み、読み戻すときに `Scan` が拒否します。`kanna-value vet` は、このような定数を、プログラムを動かさずに見つけます:

```sh
go tool kanna-value vet ./...
```

```text
usecase/orders.go:42:17: error: "shiped" is none of the constants of model.OrderStatus
  did you mean model.OrderStatusShipped?
```

報告するのは、enum のどの定数も持たない文字列の定数で、プログラムがそこから enum の値を作るところです。`==` や `!=` での比較、`case`、代入、引数、戻り値、複合リテラル、変換、関数の中や別のパッケージでの enum の型の定数の宣言が対象です。そうして宣言した定数は、使う場所ではなく、値を書いた場所で報告します。enum に生成された `NewOrderStatus` に渡す定数も報告します。こちらは毎回拒否されるので、空文字列も含みます。次のものは報告しません:

- enum のパッケージの最上位で宣言した、enum の型の定数。これが enum の値そのものです
- enum の値にする空文字列。ゼロ値で、値が未設定であることを調べたり、未設定に戻したりするために書くことがあります
- `<` などで enum の値と大小を比べる定数や、`+` や `+=` で enum の値につなげる定数。enum の値である必要はありません
- `OrderStatus(s)` のように、実行時に作る値

enum とは、`//kanna:enum` の印が付いた string 型です。検査するパッケージにあっても、それが import するパッケージにあってもかまいません。vet は enum を見分けるためにそれらをソースから読みますが、報告するのは指定したパッケージだけです。テストのファイルは検査しません。テストでは、enum が拒否する値をわざと作ることがあるからです。検査を通ったパッケージは、vet が見つけた誤りがないというだけで、誤りがないことの証明ではありません。

## ルール

`validate` メソッドは、値を受け入れるときは nil を、拒否するときは error を返します。ルールを書くためのものは、パッケージ `rule` にあります:

| 宣言 | 拒否するときの内容 |
|---|---|
| `rule.Fail(code)`, `rule.FailWith(code, params)` | 指定したコードとパラメータを持つ `*rule.Error` |
| `rule.Email(s)` | `s` が `a@example.com` のような素のアドレスでなければ `email` |
| `rule.URL(s)` | `s` が `https://example.com` のようなホスト名付きの絶対 URL でなければ `url` |
| `rule.UUID(s)` | `s` が標準のテキスト形式の UUID でなければ `uuid`。バージョンは問わない |

`rule.Email` は、net/mail がアドレスを解析するのと同じく構文だけを見ます。`a@localhost` も通り、長さや、そのアドレスにメールが届くかは確かめません。net/mail が書き直す形（引用符つきのローカル部 `"a b"@example.com` など）は拒否します。受け入れた値を、いつも書いたとおりの形で保つためです。

`rule.URL` はスキームを確かめないので、`javascript://example.com/%0Aalert(1)` も通ります。リンクとして出すなら、スキームを自分で確かめてください。

ルールはただの関数なので、普通の Go のコードとして組み合わせられます:

```go
func (CompanyEmail) validate(s string) error {
	if err := rule.Email(s); err != nil {
		return err
	}
	if !strings.HasSuffix(s, "@example.com") {
		return rule.Fail("corp_domain")
	}
	return nil
}
```

コードは破られたルールの名前で、翻訳メッセージや API レスポンスのキーに使えるほど安定した形式です。パラメータはメッセージに必要な情報を持ちます。kanna-validator は `count` 付きの `too_long` のように Rails の ActiveModel::Validations のコードを報告するので、独自のルールでも同じコードを使うと API のエラーがそろいます。エラーは `rule: too_long (count=3)` のような形式になります。拒否された値は決して含まれません。エラーはログに残るものであり、値は個人情報かもしれないからです。

## ルールを変更するとき

`UnmarshalJSON` がリクエストをルールでチェックするように、`Scan` は行を現在のルールでチェックします。そのため、ルールを厳しくすると、保存済みの行の読み取りに影響します。古いルールが受け入れて新しいルールが拒否する行はスキャンに失敗し、その行を含むクエリも一緒に失敗します。このような変更をリリースする前に、拒否されることになる行を見つけて修正または移動し、それから厳しくしたルールをデプロイしてください。enum から定数を削除する場合も同じです。定数を追加する場合も逆方向に同じことが起こります。新しい値の行ができた後にリリースをロールバックすると、その行を読み取れません。

そのような行をそのまま読まずに失敗させるのは、値オブジェクトの性質によるものです。データベースも含め、パッケージの外から来る値は、常にルールが受け入れる値だからです。

## kanna-validator との連携

[kanna-validator](https://github.com/go-kanna/validator) は、リクエストのフィールドをタグでチェックします。値オブジェクトは自分の形式を自分で守るので、そのフィールドに必要なのはせいぜい `required` だけです。kanna-validator は `required` を `IsZero` でチェックします:

```go
//kanna:validate
type SignUp struct {
	Name  string      `json:"name"  validate:"required"`
	Email model.Email `json:"email" validate:"required"`
}
```

`validator.DecodeJSON` は、`UnmarshalJSON` が拒否した値をコードとパラメータとともにフィールドのパスに記録し、デコードを続けます。そのため、レスポンスにはタグで見つかったエラーと一緒に並びます:

```json
{"errors": {"email": [{"error": "email"}], "name": [{"error": "blank"}]}}
```

enum にも `oneof` は不要です。`UnmarshalJSON` が拒否した status は `{"errors": {"status": [{"error": "inclusion"}]}}` として記録されます。

## Lint

wrapcheck は、`validate` メソッド内の `return rule.Email(s)` を、別パッケージからのラップされていないエラーとして報告します。このエラーはルールの判定結果で、ラップすべき原因はないので、パッケージを除外してください:

```yaml
linters:
  settings:
    wrapcheck:
      ignore-package-globs:
        - github.com/go-kanna/value/rule
```

## フラグ

```sh
kanna-value [flags] [packages]
kanna-value vet [flags] [packages]
```

生成:

| フラグ | 意味 |
|---|---|
| `-tags <list>` | カンマ区切りのビルドタグ |
| `-check` | 書き出す代わりに、出力が最新であることを検証する。不要な出力が残っていないことも含む。`KANNA_CHECK=1` でも同じ |
| `-v` | 書き出した、削除した、変更しなかったファイルを一覧表示する |
| `-deps` | 実行が読み書きするものを、`kanna` コマンドのために JSON で表示して終了する |
| `-version` | バージョンを表示する |

検査:

| フラグ | 意味 |
|---|---|
| `-tags <list>` | カンマ区切りのビルドタグ |
| `-version` | バージョンを表示する |

パッケージのデフォルトはカレントディレクトリのパッケージなので、`//go:generate go tool kanna-value` に引数は不要です。成功した実行は、警告以外何も出力しません。警告の 1 つは実行そのものについてのものです。対象のパッケージに `//kanna:value` も `//kanna:enum` もない場合、残っている `//go:generate` の行は無害なので実行は成功しますが、その行も消すつもりだった可能性が高いので、そのことを知らせます:

```console
$ go generate ./...
warning: nothing is marked //kanna:value or //kanna:enum in example.com/app/model
```

型のディレクティブがすべてなくなったパッケージの `value_gen.go` は、kanna-value が読み込んだパッケージのコードがその宣言をまだ呼び出していない限り、削除されます。同じ名前でも生成コードのヘッダがないファイルには触れません。削除を行う `go generate` は `open ...: no such file or directory` で終わります。これは go generate 自身のエラーで、ジェネレータを実行する前にパッケージのファイルを列挙しているためです。ファイルは意図どおり削除されています（[golang/go#36068](https://github.com/golang/go/issues/36068)）。

## サンプル

[`example`](example) は、タスクサービスの値を定数と入力から作り、それらを持つリクエストをデコードします。リクエストは、有効なもの、タグが多すぎるもの、サービス開始より前に完了したもの、enum のどの定数でもない優先度を持つものの 4 つです。さらに、渡したスライスを外部から変更できないことも示します。CI はこれを再生成して `kanna-value vet` で検査し、出力が変わる場合や vet が定数を報告した場合は失敗します。

## 開発

```sh
make test       # unit tests
make lint       # golangci-lint
make example    # regenerate the example, vet it, and run it
```
